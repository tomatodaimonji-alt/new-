# PINE 開発の最優先ルール

## 変更してはいけない基本設計
1. PINE島・海・本島は**単一座標系でシームレス**。マップデータの入れ替えや瞬間移動による「地域切替」は禁止。16マス単位のチャンクは内部描画・処理の最適化。
2. 旧住民街、畑、作物、道路、既存の白い石橋、住宅、ホテル、スーパー、漁港、避難民キャンプ、軍基地を勝手に上書きしない。
3. 建物は床・壁・窓・扉・屋根・室内を別タイルとして構築。出入りと階段とカメラの室内表示を歩行判定と連携させる。
4. 港と船は**同じ世界で実際に航行**する。船の座標・乗船場所・桟橋の歩行判定・水面の高さを整合させる。
5. エディターとゲーム本体でブロックID、3D形状、回転、床・障害物・扉判定を対応させる。共通化未済のコードは双方を修正する。
6. 無断の機能削除・UI縮小・既存データ変更・マップ自動置換をしない。
7. Android WebView、オフライン、外部APIなし、完成物は単一HTML。開発用コードだけ分割する。
8. 端末への負荷を抑える。無限の遠景ジオメトリ生成、毎フレーム全ワールド再構築、不要なGPUバッファ再確保を避ける。

## 作業ルール
- 最初に `docs/HANDOFF.md` と本書を読む。関連ソース・隣接機能・元の仕様を確認してから修正する。
- GitHubの最新SHAを読んでから更新する。ユーザーの元コードを別の簡易作品へ置き換えない。
- 変更は原則 `src/` 内で実施し、`node scripts/build.mjs` で2つの完成HTMLを生成する。既存の `forest-game-prototype.html` と `world-editor.html` のプレイ方法は維持する。
- ビルド整合性 `node scripts/build.mjs --check`、`node scripts/test-build.mjs`、構文検証を必須とする。ブラウザとAndroidのテストは別であり、実施しなければ「未検証」と記す。
- 重要変更は `docs/CHANGELOG.md` と `docs/HANDOFF.md` に追記。日時、差分、未完、既知の問題を記録。
- 仕様の矛盾が見つかった場合は、勝手に過去仕様を上書きしない。現状と意図を区別する。

## 分割の段階
第1段階（今回）：**元HTMLと文字単位で同じ出力の断片へ分割**。まだ各JSファイルは自立したES Modulesではない。
第2段階（今後）：共通3D形状・ブロックカタログ・歩行判定を段階的に共有化。
第3段階（今後）：島／本島のチャンク永続化・負荷テスト・モバイル操作の回帰テスト。
