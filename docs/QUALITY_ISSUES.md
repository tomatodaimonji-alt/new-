# PINE 失敗・改善記録（再発防止台帳）

この台帳は **改修前に必ず参照する**。新規登録前に類似項目を探し、同じ根本原因・対策なら既存項目に統合する。ユーザーの好みや新しい仕様の要望は、明確な不具合と区別する。過去の事例は削除せず、軽微な個別経緯は GitHub コミット履歴へ集約する。

## 記録する基準
- **登録**：同じ失敗を繰り返しやすい、既存データ・機能・操作に影響する、または原因と対策が一般化できる問題。
- **統合**：症状や発生画面が異なっても、原因・防止策が実質的に同じ問題。再発回数と関連範囲を追記。
- **別登録**：症状が同じでも原因・検査方法が明確に異なる問題。
- **台帳への新規登録を省略**：単なる希望変更、既存項目に統合可能なもの、再発リスクの低い一時的問題。必要ならコミット履歴へ残す。
- **再発時**：項目をコピーせず再発回数を更新し、効果のない対策は見直す。対策が静的テストで検証可能なら、テスト化を優先する。
- **根拠区別**：「現象を確認」「原因を推定」「コード検査済み」「Android実機で確認済み」を混同しない。

## 改修時の必須手順
1. `docs/PROJECT_RULES.md` と本書を読む。改修対象に関連する項目を確認する。
2. 現状コード・保存形式・ゲームとエディターの責務を確認し、既存コード改修を優先する。
3. 変更前に回帰リスクと検証手段を特定する。問題の実例だけでなく**再発防止策**を適用する。
4. 構文・ビルド整合性・静的回帰テストを行い、可能な範囲でブラウザとAndroid実機を確認する。未実施は未検証と明記する。
5. 新たな失敗・再発・検証結果を、重複のない形で本書へ反映する。

## 現在の重要項目

### Q-001｜誤ったアプリ・ファイルへの改修
- **現象**：POIを独立したワールドエディターへ実装すべきところ、ゲーム本体や別の専用HTMLを編集した。
- **対策**：作業前に目的ファイルを明示する（ゲームは `forest-game-prototype.html`、エディターは `world-editor.html`）。原則 `src/game/` または `src/editor/` で変更し、意図せぬ両アプリ変更を避ける。
- **検証**：変更ファイル一覧とビルド差分を確認。APKの自動更新対象も確認。
- **再発回数**：履歴の集計未実施。

### Q-002｜歩行・カメラ・屋根の表示不具合
- **現象**：POI歩行中のガタつきや屋根のちらつき、歩行開始時に屋根が先に消える問題が指摘された。
- **対策**：キャラとカメラの移動補間を同期し、屋根は屋内判定で切替。描画面の重なりや不要なGPUバッファ再生成を避ける。既存の共通処理を優先する。
- **検証**：長押し連続歩行・方向転換・出入口往復・屋根切替を実際の描画で確認。構文検査のみでは合格扱いにしない。
- **原因の確度**：補間不一致などはコード上の改善対象。実機で全原因の特定・解消は未確認。
- **再発回数**：履歴の集計未実施。

### Q-003｜POIの外観・配置品質が不十分
- **現象**：スーパーの入口数、孤立した部屋、駐車区画線の不足、車両の造形、商品棚の単調さなどに対し改修要望があった。
- **区分**：主に品質改善・仕様調整。すべてを「バグ」とは扱わない。
- **対策**：現実の写真・構造資料を先に確認し、入口・動線・敷地・看板・屋根・車両の寸法と配置を一体で設計。部材の新設前に既存のものを再利用できないか確認する。
- **検証**：POI種類ごとに入口数と客用動線・内部の到達可能マス・白線・車種を検査し、外観・歩行導線をブラウザまたは実機で目視確認。車オブジェクトとショッピングカートは部分文字列一致による誤判定を避ける。
- **再発回数**：集計対象外（品質改善群）。

### Q-004｜静的検査と実機反映の混同
- **現象**：GitHubのHTML更新とAPKへの反映、構文・生成テストの成功とAndroidでの見た目・操作の成功は別の状態である。
- **対策**：コミット済み／ビルド済み／静的テスト済み／ブラウザ検証済み／Android実機検証済み／APK反映確認済みを区別して報告する。
- **検証**：GitHubコミットとビルド結果を確認。更新版表示やAndroidの挙動は実機確認できた場合のみ「確認済み」と記載。
- **再発回数**：履歴の集計未実施。

## 台帳のメンテナンス
- 原則として短い「現象・原因の確度・対策・検証・再発」の5要素だけ保持する。
- 同種事例は追加の見出しにせず既存項目へ統合し、冗長な経緯はコミット・CHANGELOGへ委ねる。
- 不要なコードを増やさず既存コードから修正する規則は `docs/PROJECT_RULES.md` を正本とし、ここへ重複記載しない。
